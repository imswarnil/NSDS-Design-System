Read `readme.md` first, then explore the other files.

**The one thing to understand before writing any code here:** this system feeds
**two** products — a Ghost theme (Handlebars + Tailwind v4) and a Next.js LMS
(React). So the styling lives in a portable `.ns-*` CSS layer
(`components/css/`), the React components are thin renderers over those
classes, and `templates/` holds the framework-agnostic HTML contract each
stack adapts. Never style a React component inline; that
produces something the Ghost theme has to reimplement. `docs/INTEGRATION.md` is the
contract between the two.

**The type scale forks, and picking the wrong half is the most common mistake.**
`--size-body` (14px) is the **UI** size — rails, tables, admin, player chrome,
cards, anything SCANNED. `--size-prose` (17px) / `--size-prose-lead` (20px) /
`--size-prose-small` (15px) are the **reading** scale, for `.ns-prose` and
anything inside an article: callouts, comments, references, notices, code
blocks in a post. Leading forks with it: prose paragraphs run
`--leading-prose` (1.7), UI runs `--leading-body` (1.6), and multi-line UI
text that is scanned rather than read takes `--leading-snug` (1.45). The axis is scanned-versus-read, not big-versus-small. Never
set an article at `--size-body` or a table row at `--size-prose`.

**Tokens are the source of truth and are enforced.** `tokens/*.css` is authored;
`tokens.json`, `tokens.js`, `tokens.d.ts` and `tokens/tailwind.css` are
generated by `npm run build`. A raw color, radius, z-index, transition timing,
font-family or padding value in the component layer fails `npm run check`.

If creating visual artifacts (slides, mocks, throwaway prototypes), copy assets
out and create static HTML files for the user to view — link `styles.css` or
`dist/namaste-ui.css` and use the `.ns-*` classes. If working on production
code, read the five Design Principles in `readme.md` and
`guidelines/accessibility.card.html` and become an expert in designing with this
brand.

If the user invokes this skill without other guidance, ask what they want to
build or design, ask some questions, and act as an expert designer who outputs
HTML artifacts _or_ production code, depending on the need.
